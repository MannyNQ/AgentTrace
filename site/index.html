The gate on every pull request

agenttrace eval runs your agent over every item, several times each, grades the outputs and the tool calls, and compares the result with the run at your merge-base. In CI, the GitHub Action posts the comparison on the PR and holds the check on a regression.

Line clear no significant drop.

Underpowered the drop is there, but 4 items can’t prove it at 95%. Flagged, never gating.

Line blocked the interval is below zero and the drop beats max_drop: exit 3, the PR is held.

A gate that won’t cry wolf: with 4 items, a 50-point drop can’t be told from noise at 95%, so the check passed, said why, and named both items that broke. A softer edit, “answer policy questions directly”, changed nothing the scorers could see, and the gate stayed quiet.

Rule 25

How the gate decides

25.1
The metric. Each scorer’s pass rate: the share of samples scoring at or above its pass threshold, over the items scored in both runs.
25.2
The interval. A paired, item-level bootstrap: 10,000 rounds, each drawing items with replacement and taking all of their samples from both runs. The 95% interval is the 2.5th to 97.5th percentile. The seed is fixed.
25.3
A regression. The whole interval is below zero, and the drop is larger than the scorer’s max_drop (5 points unless you set it). Then --fail-on-regression exits 3.
25.4
Underpowered. The interval’s half-width is larger than max_drop, so a drop of that size could go undetected. Flagged per scorer; it never changes the verdict.
25.5
Item regressions. Items where most samples passed before and most fail now. Listed by ID, never gating.

Rule numbers follow the decision record: ADR-0025, paired item-level bootstrap with max_drop.

Check the fix against the run that failed

Re-run a failed trace with the code on your branch. agenttrace replay calls your agent three times with that trace’s input, scores each run against the dataset item made from it, and with --require-pass exits 3 unless every run passes. The replay page shows each run beside the original, marked where they first differ.

Test train · the PR’s failed trace

agenttrace replay 1dc1fb97… -c eval.yaml --require-pass
  • Exit 0 every replay passes the item’s expectations.
  • Exit 3 any replay fails; the fix isn’t proven.

Your traces, your machines

License

MIT. Read it, fork it, run it.

Stack

Docker Compose. Postgres, ClickHouse, Redis, and S3-compatible storage, on one host.

Code

Your agent stays yours. Evals and replays run on your machine or in your CI; the server never executes your agent.

Keys

Scoped. An ingest key can only send spans. A full key runs evals.

Run it locally

Needs Docker, uv, and pnpm. The OpenTelemetry demo agent runs on a scripted model, so you don’t need an API key to see your first trace.

  1. 1Get the code and start the stack
    git clone https://github.com/MannyNQ/AgentTrace && cd AgentTrace cp .env.example .env docker compose up -d --wait
  2. 2Start the web app, then claim it at localhost:3000/setup
    cd web && pnpm install && pnpm dev
  3. 3Send a trace from the demo agent
    uv sync --all-packages uv run demo-agent-otel "Where is order 1042?"
