# Glossary

The vocabulary AgentTrace uses in code, UI, docs, and issues. Use these terms exactly; don't drift to the synonyms listed under "Avoid".

## Tenancy

**Org**: The top-level owner of projects and users. A self-hosted install has one org, the default one; the schema allows more, but the UI assumes one.

**Project**: One agent or app being monitored. Every span, dataset, and experiment belongs to exactly one project, and every query is scoped by `project_id`. Every member of the org can see every project. See ADR-0002.

**Project slug**: A project's URL name, as in `/p/<slug>/traces`. Generated from the name at creation, unique within the org, and never changed; the name stays editable. The default project's slug is `default`. Session requests to the API name their project with it in the `AgentTrace-Project` header (ADR-0032).

**User**: A person with an account: an email, an argon2id password hash, and one org membership. Created by claiming the install or accepting an invite. Deactivated, never deleted.

**Member**: A user's place in the org, with a role. Also the role `member`, which can do everything in every project except what's reserved for owners. _Avoid_: per-project member, since there are no per-project access lists.

**Owner**: The role that manages members, invites, roles, API keys, projects, and project settings such as `retention_days`. The org always has at least one.

**Session**: A logged-in user's access, an opaque token held by ingest (hashed) and by the web app in an httpOnly cookie. Lasts 30 days, sliding. See ADR-0032. _Avoid_ confusing it with Session ID, which groups traces.

**API key**: A secret that authenticates the SDK, the CLI, or CI as one project. Shown once, stored as a SHA-256 hash, revoked rather than deleted. The key from `AGENTTRACE_API_KEY` is re-added on every startup and can't be revoked in the UI; the published dev key `at-local-dev-key` is accepted only while `AGENTTRACE_PUBLIC_URL` is localhost. See ADR-0017 and ADR-0033.

**Key scope**: What an API key may do: `ingest` (send spans only, for agents in production) or `full` (the whole project API, for the CLI and CI). See ADR-0033.

**Invite**: An owner-created, single-use link, valid for 7 days, that lets a person create a user with the role chosen in the invite. Password-reset links work the same way. Deactivating a user voids the unused links they made. There is no email.

**Setup token**: The secret needed to claim an install that has no users yet, from `AGENTTRACE_SETUP_TOKEN` or printed in ingest's logs. Claiming creates the first owner. See ADR-0034.

## Tracing

**Trace**: One end-to-end agent run, from the incoming request to the final answer. Identified by a 16-byte hex `trace_id` generated by the SDK. See ADR-0003.

**Span**: One unit of work inside a trace. Spans nest into a tree through `parent_span_id`. Identified by an 8-byte hex `span_id` generated by the SDK; `(trace_id, span_id)` is unique.

**Payload**: A span's full input or output. Values over 8 KB are moved to object storage; the span keeps a **preview** (first 1 KB) and an `input_uri` or `output_uri`. Search covers previews only. See ADR-0009.

**Root span**: The span with no parent. Its end marks the trace complete. See ADR-0004.

**Span kind**: A closed set: `llm`, `tool`, `agent`, `retrieval`, `custom`. `custom` is the escape hatch; no other kinds exist.

**LLM span**: A span of kind `llm`. Carries the model, input messages, completion, token counts, cost, and parameters directly as fields. _Avoid_: Generation.

**Tool span**: A span of kind `tool`: one function or tool execution, with its arguments and result. An MCP call is a tool span with an `mcp.server` attribute.

**Session ID**: An optional string on a trace that groups traces from one conversation or user thread. Not an entity; nothing is stored about a session itself. _Avoid_: Session (as a table or object).

**Trace completion**: A trace is complete when its root span ends, or after a 5-minute quiet period with no new spans. A late span reopens the trace and its summary is recomputed. See ADR-0004.

**Trace summary**: Derived fields on a complete trace: total latency, cost, span count, status, error counts per span kind, and the root span's `replay_of`, if any.

**Trace status**: `error` when the root span is `error` or never closed; otherwise `ok`. A failed span the agent recovered from doesn't make the trace `error`. A trace that isn't complete yet shows as `running`. Status is computed when a trace is read (ADR-0013).

**Trace metadata**: Set on the root span by the SDK: `session_id`, `user_id`, `tags` (list of strings), `metadata` (string-to-string map). Tags and user ID are filterable.

**Cost**: `cost_usd` on an LLM span, computed once at ingestion from the price table and never recomputed. Covers input, output, and prompt-cache reads and writes (`input_tokens` excludes cached tokens). Null when the model has no price. See ADR-0010. OTel conventions count cached tokens inside input tokens, so OTLP ingest subtracts them, and counts every cache write as a 5-minute write, since no convention says which (ADR-0035).

**Price table**: Versioned prices per model (input, output, cache-read, and 5-minute and 1-hour cache-write per-token prices, effective date).

**Retention**: Spans expire after a per-project period (default 30 days). Traces linked from a dataset item are **pinned** and never expire; experiment traces and replay traces expire normally. See ADR-0011, ADR-0021, and ADR-0029.

**Pin**: Exempting a trace from retention by rewriting its `retention_days` in `spans` and `traces` so it expires on 2106-01-01, the latest date ClickHouse's `DateTime` holds. Happens when a dataset item gets a `source_trace_id`. Unlinking doesn't unpin. See ADR-0021.

**OTLP ingest**: The `POST /otlp/v1/traces` endpoint, which takes spans from any OpenTelemetry exporter over OTLP/HTTP and translates each one into a span, stored like any other. Authenticated by an API key, as `/v1/spans` is. A span that can't be stored is dropped and reported back rather than failing the request. See ADR-0035.

**OTel bridge**: The SDK's in-process version of the same translation. It turns OpenTelemetry spans into spans as they end, so the eval runner sees an OTel-instrumented agent's trajectory. The eval runner and `agenttrace replay` install it automatically; elsewhere it's installed with `agenttrace.otel.install()`. See ADR-0036.

**Convention**: The attribute vocabulary an OpenTelemetry span was translated from: `gen_ai` (OpenTelemetry's GenAI conventions), `openinference`, or `none`, recorded in the span's `agenttrace.convention` attribute. A span with neither becomes a `custom` span. _Avoid_: semconv, as shorthand.

## Evals

**Trajectory**: The ordered sequence of tool spans in a trace (tool names and arguments). What trajectory scorers grade. See ADR-0001.

**Dataset**: A named set of test cases in a project. Has one editable draft and a series of immutable published versions. See ADR-0005. Identified by a stable `id`; its name can change. Datasets are **archived**, never deleted: an archived dataset is hidden from the dataset list and the "Add to dataset" picker, and its versions stay readable. _Avoid_: deleting a dataset.

**Dataset version**: A frozen snapshot of a dataset (`v1`, `v2`, ...), created by publishing the draft. Stored as one item revision per item; unchanged items share their revision with the previous version. Experiments always pin one. See ADR-0020.

**Item revision**: One immutable state of a dataset item's contents, numbered `rev` 1, 2, ... per item. Editing a draft item adds a revision. Edits name the revision they were based on, and a stale one is refused.

**Publish**: Freezing the draft into the next dataset version. Refused when nothing changed since the latest version, or when a new or changed item has neither an expected output nor an expected trajectory.

**Dataset item**: One test case, with a stable `item_id` that persists across dataset versions (each version records the item's contents at that point): `input`, plus optional `expected_output`, `expected_trajectory`, `metadata`, and `source_trace_id`.

**Expected trajectory**: A list of tool calls a dataset item should produce, each `{"tool": "<name>", "args": {...}}` with `args` optional. `args` is a partial match: the listed keys must be equal, other keys are ignored. Records what should happen; matching modes, regex and wildcards are the scorer's job.

**Add to dataset**: Turning a trace into a draft dataset item. The server copies the root span's full input into the item at that moment (fetching it from object storage if it was offloaded) and sets `source_trace_id`; it leaves `expected_output` and `expected_trajectory` empty to fill in, since the trace's own steps are the failure. A trace can be in a dataset's draft once. _Avoid_: Promote, Capture.

**Source trace expired**: A dataset item whose `source_trace_id` points at a trace that retention has removed. The item still works, since it holds its own copy of the input; only the link to the evidence is gone. Pinning stops this for items created from Phase 3 on, and ingest's startup pass pins earlier links whose traces still exist (ADR-0021).

**Scorer**: A function that grades one sample. Built-ins (exact match, contains, regex, JSON schema, trajectory, LLM judge) are configured in `eval.yaml`; custom scorers are Python functions referenced by import path. A scorer is skipped for an item that lacks the expectation it needs.

**Trajectory scorer**: The built-in scorer that compares a trace's trajectory to an expected trajectory in one of these modes: `exact`, `in_order`, `any_order` (against the item's expected trajectory), `forbidden`, `max_steps` (parameters from the scorer config). Scores 1 or 0.

**eval.yaml**: The eval config in the user's repo: the entry point (`module:function`, called with the item's `input`), dataset and `version` (a number or `latest`), scorers with their pass thresholds and `max_drop`, `samples`, `concurrency`, and `timeout_s`. Its hash, over the parsed config as canonical JSON without `name`, `concurrency`, `version`, and `max_drop`, decides which experiments can be compared. See ADR-0022 and ADR-0023.

**Eval runner**: The CLI process (`agenttrace eval`) that runs the user's agent over a dataset version, scores the outputs, and uploads results. Runs on the user's machine or in their CI, never on the server. `agenttrace replay` runs replay runs through it unchanged. See ADR-0006.

**Experiment**: One run of one version of the agent over one dataset version with a set of scorers. Status is `running`, `completed`, or `failed`; `failed` means the runner failed, not the agent. See ADR-0023.

**Sample**: One run of the agent on one dataset item within an experiment. Each item runs `samples: k` times (default 3); results report mean and spread across samples.

**Errored sample**: A sample whose agent call raised or exceeded `timeout_s`. Every scorer scores it 0 with a reason naming the error; the experiment still completes.

**Score**: A scorer's result for one sample: a number from 0 to 1 plus an optional `reason`. The sample passes that scorer when the score is at or above the scorer's **pass threshold** (default 1.0).

**Baseline**: The experiment a pull request's experiment is compared against: the newest completed experiment at the merge-base commit with the same `eval.yaml` hash, else the newest on the PR's base branch with that hash, else none. The CLI records the merge-base and base branch, since the server has no git repo. See ADR-0007 and ADR-0026.

**Comparison**: An experiment set against its baseline, computed by ingest so the PR comment and the UI agree: per-scorer pass rates with the change and its 95% bootstrap CI, regressions, item regressions, cost and latency, and items added or removed. Both experiments must be `completed` with the same `eval.yaml` hash. See ADR-0024.

**Metric**: One scorer's pass rate over the items scored in both runs of a comparison. Cost and latency are compared but aren't metrics: they never gate. See ADR-0025.

**max_drop**: A scorer's largest tolerated pass-rate drop, in absolute points (default 0.05). Set per scorer in `eval.yaml`, outside the hash. _Avoid_: threshold, which means the pass threshold.

**Regression**: A metric whose drop versus the baseline is both statistically real (the 95% paired item-level bootstrap CI of the change lies below zero) and larger than its `max_drop`. Fails the CI check under `--fail-on-regression` (exit 3). See ADR-0008 and ADR-0025. _Avoid_: calling any score drop a regression.

**Underpowered**: A metric whose CI half-width is larger than its `max_drop`, so a drop of exactly `max_drop` couldn't be detected. Flagged in the comparison; doesn't change the gate.

**Item regression**: A dataset item and scorer where more than half the item's samples passed that scorer in the baseline and more than half fail it now. Listed in the PR comment; doesn't fail the check by default.

**LLM judge**: The `llm_judge` scorer: an Anthropic model, named in `model`, grades a sample against plain-language `criteria` and returns pass or fail with a reason. Runs in the eval runner, outside the sample's trace; after 3 failed retries it skips the sample rather than scoring 0. See ADR-0027.

**Judge cost**: `judge_cost_usd` on a sample, computed by the server from the judge's token counts, kept apart from the agent's cost. See ADR-0027.

## Replay

**Replay**: One re-run of a recorded trace's root input through the user's entry point, `--samples k` times (default 3), started with `agenttrace replay <trace_id>`. Stored as one `replays` row with a status (`running`, `completed`, or `failed`), its git commit, branch, and dirty flag, and its runs. Scored only when the trace is the `source_trace_id` of an item in `eval.yaml`'s dataset draft and the item has an expectation; the runs are then scored against that draft revision, recorded as `(item_id, rev)` (ADR-0030). Not an experiment: it pins no dataset version. See ADR-0028 and ADR-0029. _Avoid_: calling a replay run a Sample.

**Replay run**: One execution within a replay, and its own trace. Its root span carries `replay_of`, the `(trace_id, span_id)` of the original trace's root span. Replaying a replay points at the original's root span, so `replay_of` never chains. Errored runs score 0, as in an errored sample. See ADR-0028. _Avoid_: Sample, which is an experiment's run.

**First difference**: The first position where a replay run's trajectory differs from the original's. Trajectories are compared step by step; a step differs on tool name or on `args` by full JSON equality, not the partial match of an expected trajectory, because the original is a recording, not an expectation. A trajectory that is a prefix of the other differs at the first missing step. Outputs are shown side by side with no computed diff.

## Analytics

**Overview**: A project's landing page, `/p/<slug>/overview`: volume, error rates, latency percentiles, cost, and tools over 24h, 7d, or 30d, with each headline number's change from the previous period. Its numbers are approximate (ADR-0037). _Avoid_: dashboard, as the page's name.

**Trace filter**: The one set of conditions the trace list and the overview both take: time range, status, tags, user ID, service name, production or eval and replay runs, and spans of a kind or name. A chart click opens the trace list with the same filter, so the two agree. See ADR-0038.

**Production traffic**: Traces that are neither eval samples' traces nor replay runs. The overview counts only these unless told otherwise.

**Service name**: `service_name` on a trace, from its root span's `resource.service.name`: an OpenTelemetry resource attribute over OTLP, or `AGENTTRACE_SERVICE_NAME` (else `OTEL_SERVICE_NAME`) in the SDK. Empty for traces stored before Phase 8.
